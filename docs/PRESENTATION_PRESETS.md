# Presentation Presets: audited cross-category increment

The token/timing foundation now also covers all three verbosity profiles, Menus, Hotkeys, Key Labels, two presentation-related Misc options, Browse/Focus indication and the two Advanced startup-announcement controls. Never serialize all of General Settings. These are editable presentation settings, not another screen reader's navigation features.

## Implemented contract

Preferences > ClassicSpeech > Presentation Presets opens the existing manager in a standalone native dialog; General Settings starts with Verbosity. No duplicate manager or hidden General panels remain. The unbound Input Gestures script queues the same opener; no default gesture is added. Its native list selects only; Load is explicit. Save as, Update, Rename and Delete stage a working library. Protected ClassicSpeech defaults uses `VerbosityManager.DEFAULT_SHAPE`, the five editable detail defaults from `VerbosityManager.PROFILES`, `_default_profile_behavior` for each profile and existing menu/hotkey/key-label/Misc defaults. It is not native NVDA reset or a user's personal baseline. Modified status compares only supported domains present in the loaded record. Load asks before discarding modified content.

The new `presentationPresets` base-only scalar is registered in `plugin_config.py`. It is versioned JSON carried by the existing `settings_file.py` boundary to `ClassicSpeech/settings.ini`. Apply/OK accepts staged library edits in memory, without a new filesystem-save boundary. Cancel/Close restores the last accepted raw owned-leaf snapshot, including library presence and owned shape/profile/message leaves, and restores the exact active runtime profile and shape. Unknown and unrelated keys are not rolled back. General and Web dialogs cannot overlap this transaction; opening one raises the existing dialog. Voice Profiles and Schemes are not blanket-blocked. Ordinary General Settings Apply still saves its existing controls; the preset library itself writes only its one scalar.

Schema version 1:

- `version`: integer 1. Unsupported versions make the library read-only. The exact raw payload is preserved through ordinary settings actions, including loading built-in defaults and Apply/OK/Cancel/Close; no implicit downgrade or replacement is permitted.
- `records`: stable generated ID to `{name, domains}`.
- `domains.tokens`: `order`, `renames`, `mutedLabels`.
- `domains.timing`: `pauseMode`, `globalPause`, `pauses`, `pausePlacement`, `pauseAfterFinalToken`.
- `loaded`: optional last explicitly loaded/saved/updated ID, used for status only, never automatic application.

`settings/presets/model.py` declares the current domain allowlist. Known domains must contain complete validated fields. Unknown future domains and unknown fields inside known domains remain opaque, preserved through Rename/Update/serialization, and never applied. Update replaces only allowlisted fields (including complete known rename/mute maps), retaining opaque siblings. Unknown versions and invalid records fail closed to the current presentation. Names are unique after trimming and case folding; maximum 80 characters. The library is bounded to 100 user presets and 600,000 encoded JSON characters. Labels and rename maps are bounded; stored pauses are integers from -1 through 2000 (global cannot be -1). Existing current settings outside these format bounds are kept rather than reset. Percent signs are JSON-escaped to prevent ConfigObj interpolation of user text.

`presets/domains.py` declares the additional allowlists, each with integer `version: 1`; `config_adapter.py` owns scoped configuration/runtime capture/application without panel instances. `transaction.py` owns exact raw allowlisted leaves, ancestor presence, selected runtime profile, and native write-target snapshots. Old token/timing presets leave missing newer domains unchanged, never defaults-reset. Save as captures all currently supported domains. Update adds missing supported domains while retaining opaque fields, including nested future verbosity leaves. Known domains with unsupported future versions remain opaque and are neither applied nor overwritten. Out-of-format current settings remain readable/live; Save as/Update rejects an unrepresentable snapshot instead of resetting it.

## Single-preset import and export

The existing manager also has native **Import…** and **Export…** buttons. File dialogs run directly from their native button events, not from NVDA's core pump. Cancel is silent. Results and errors are announced once through `message_priority.speak_message`, without moving focus or loading anything.

- Export writes only the selected **saved user record**, including its saved name and opaque fields. It never captures unsaved live presentation changes, the loaded/reference metadata, the rest of the library, or the whole configuration. Export is unavailable for no selection and the generated protected ClassicSpeech defaults; use Save as first to create an exportable saved copy. This avoids pretending a generated, installation-dependent default record is saved content.
- Export writes immediately and independently of Apply/OK/Cancel. Cancelling the settings dialog does not delete an exported file. The native Save dialog confirms overwriting. The writer validates/encodes first, writes and flushes a temporary file in the destination directory, closes it, then uses `os.replace`; failures before replacement cannot truncate an existing destination. Temporary files are cleaned up.
- Import validates a bounded UTF-8 JSON file before changing the working library. It selects a newly generated ID but does **not** Load it, apply runtime settings, or change loaded/reference/modified presentation state. Apply/OK accepts the staged record; Cancel/Close discards imports since opening or the last Apply. Native NVDA configuration save persists the accepted library through the existing settings.ini route, without an immediate import disk save.
- Names use the existing trimmed, case-insensitive unique-name rules. A collision, including the protected defaults name, opens the existing name editor; cancelling makes no mutation. No silent overwrite or replacement is allowed. Unsupported future libraries disable and reject Import while preserving their exact raw data. Capacity/serialized-size failure is checked against a copied candidate before mutation.

Portable file version 1 is one object with `format: "ClassicSpeech presentation preset"`, integer `version: 1`, and `preset: {name, domains, ...opaque record fields}`. The portable version is independent of library/domain versions. The file is limited to 600,000 **bytes**, read at most one byte beyond that limit; it is not an archive, pickle or executable format. Malformed UTF-8/JSON, duplicate JSON keys at any depth, nonfinite numbers, Boolean/null/string or unsupported file versions, invalid structures and invalid known semantic values are rejected. Existing domain validators remain authoritative; missing newer domains leave those settings unchanged on a later explicit Load, and future domain versions remain opaque. Library count/encoded-character bounds still apply separately.

The audited known presentation domains below are the only configuration values captured. No voice settings, secrets, machine paths, settings.ini/nvda.ini dump, updater preferences or operational configuration are automatically added. Unknown record fields, sibling domains and nested future fields are preserved as declarative JSON for forward compatibility, never executed or applied; imported opaque data is not a privacy scrubber. Review shared files if another producer attached private metadata. Literal labels/messages remain in their saved language; importing does not translate them.

## Audited ownership inventory and exact keys

The following is the implemented allowlist, not a whole-General snapshot:

- **Tokens — implemented:** `settings/token_editor_panel.py`, `settings/shape_config.py`; global `shapeData.order`, `renames`, `mutedLabels`. Panel owns only those fields when previewing.
- **Timing — implemented:** `settings/speech_timing_panel.py`, `settings/shape_config.py`; global `shapeData.pauseMode`, `globalPause`, `pauses`, `pausePlacement`, `pauseAfterFinalToken`. It merges only its fields into the latest live shape, so alternating Token/Timing edits cannot undo each other. Nonstandard valid pause values are represented in native choices rather than silently coerced.
- **Menus:** domain `menus` contains `version`, `announceMenuOpen`, `announceMenuClose`, `announceMenuBarFocus`, `announceMenuBarLeave`, `menuOpenMessage`, `menuCloseMessage`, `menuBarFocusMessage`, `menuBarLeaveMessage`, mapping directly to ClassicSpeech base keys. Blank messages use the panel's trim/fallback semantics: `Entering menu`, `Leaving menu`, `Menu bar`, `Leaving menu bar`. Disabled message values are retained. Loading writes only these configuration leaves; editing controls remain in General Settings.
- **Hotkeys:** domain `hotkeys` contains `version`, `mode`, `format`, `types`, `dialogAccessKeyOnly`, mapping respectively to base `hotkeyMode`, `hotkeyFormat`, `hotkeyTypes`, `hotkeyDialogAccessKeyOnly`. All existing string enums/checklist combinations and disabled dependent values remain supported. `_set_hotkey_mode` intrinsically synchronizes native `presentation.reportKeyboardShortcuts` through the backup wrapper; this native value is not saved in presets.
- **Verbosity:** domain `verbosity` contains `version`, `defaultProfile`, and `profiles.Beginner`, `.Intermediate`, `.Advanced`. Each profile contains `enabledTokens.name`, `.role`, `.state`, `.description`, `.tooltip`, `positionMode` (`off`, `first`, `each`), and `readEditFieldContents`. Storage is `profileData.<name>.enabledTokens` and `profileBehaviorData.<name>`. Active `positionMode/readEditFieldContents` are derived mirrors. Value/position/hotkey enabled-token leaves are not separate verbosity choices: existing manager normalization forces them on; position behavior and Hotkeys own their reporting. No active/unseen profile or future profile leaf is deleted. `set_shape_config(save=True)` remains shape-only. Verbosity refreshes its legacy combined shape payload before preview/save/switch/reset. Tooltip overrides now reload alongside ordered-token flags: Tooltip is editable verbosity even though absent from token ordering; focused tests caught the prior omission.
- **Selected Misc:** domain `misc` contains only `version`, `includeWindowStateInTitle`, `announceDefaultButton`, mapping directly to those base keys. They are presentation announcements. No report-application option is invented. Exclude `queryObjectSource` (changes command source), `objectNavigationProcessing` (processing scope), `preventAutomaticSpeechInterrupt` (interrupt policy), `prioritizeMessages` (service/delivery priority), `automaticSpeechInterruptFallbackMs` (controller timeout, not presentation pause; not a current exposed Misc control), native `presentation.guessObjectPositionInformationWhenUnavailable` (inference preference), and native `keyboard.speechInterruptForCharacters` / `speechInterruptForEnter` (interruption behavior). Loading never calls whole-Misc save.
- **Key Labels:** domain `keyLabels` contains `version`, complete `renames` and `mutedLabels`, mapping to `keyLabelData`. These are distinct from object-token labels. Existing canonical key identities, native input-help bypass and deferred editor callback invalidation remain intact.
- **Browse/Focus messages:** domain `messages` version 1 owns `browseModeMessage`, `focusModeMessage` (base `modeIndicationData`) and native `virtualBuffers.passThroughAudioIndication` (Boolean). The three controls stay exactly in Web / Browse Mode Settings. Canonical defaults are blank messages plus audio enabled, verified against native configSpec at reference `2843e703c`. Sound mode retains custom strings; blank messages continue through the existing localized native fallback. Legacy records without this domain leave it unchanged; future domain versions remain opaque. No speech routing or filter is changed.
- **Other domains not captured:** Text Processing, Number Processing, Document Reading / Proofing and other Web / Browse Mode settings. No accidental native document/proofing baseline capture.
- **Speech hook startup announcement:** domain `speechHookAnnouncement` version 1 owns exactly Boolean `announceSpeechHookLoaded` and string `speechHookLoadedMessage`, mapping to those base keys. These are the only Advanced exceptions. Editing stays in the existing Advanced checkbox/text field. Canonical defaults match configSpec: false and `ClassicSpeech hook loaded`. Capture reads stored text without invoking the materializing Advanced getter: missing uses the schema default; explicitly blank or whitespace text remains raw (the existing spoken getter still trims/falls back). Application writes only these two leaves, without speaking the startup message, enabling/restarting the hook, or changing voices. Only existing preset-loaded feedback is emitted. Save as/Update and single-record transfer include the domain; older partial records leave both leaves unchanged and compare modified status only in their captured scope. Known v1 fields require exact Boolean/string types and bounded single-line text; future fields/versions remain opaque under the existing rules. Cancel/Close and failed Load restore exact raw values/presence; Apply establishes the new baseline, without forcing a configuration save.
- **Remain excluded:** voices, Speech and Sound Schemes, updater/channel preferences, diagnostic/hook-debug settings, and other native NVDA preferences/baseline. Only mode-indication audio is explicitly captured. No broad dump or implicit future-domain application.

## Verification boundary

Intrinsic native effects are exactly `presentation.reportKeyboardShortcuts`, `reportObjectDescriptions`, `reportTooltips`, `reportObjectPositionInformation`. They are derived from ClassicSpeech intent, not native preset domains. `settings/native_state.py` snapshots/restores exact raw values and presence in the actual native write-target profile, using `nvda_settings_backup` for recorded writes. It also preserves General's pre-existing unrelated Misc leaves `presentation.guessObjectPositionInformationWhenUnavailable`, `keyboard.speechInterruptForCharacters`, `keyboard.speechInterruptForEnter`. No native section is replaced. Private backup target/raw-state/cache-refresh helpers are reused; their internal contract is a maintenance risk covered by tests.

Load applies existing configuration/runtime helpers directly in its own transaction. No editing panels are constructed or synchronized; accepted settings are captured. General retains its independent three-profile working registry and token/timing ownership. Apply/OK accepts in memory; Cancel/Close restores only owned raw data, profile leaves, runtime and exact native leaves, preserving unrelated changes. Native snapshots also include audio indication. Ordinary destruction and plugin unload restore unaccepted previews and release the popup idempotently. Existing configuration-save boundaries remain unchanged.

Advanced working-copy safety follows that same standalone architecture: the manager's actual adapter is `presets/config_adapter.py`, not a hidden General/Advanced instance. The existing bidirectional General/presets opener guard prevents simultaneously open stale Advanced controls. After accepting Load and closing the manager, the next General constructor builds the real Advanced controls from the newly accepted values; subsequent Advanced live edits and General Apply cannot replay a pre-Load copy. The focused announcement harness exercises this real panel path, Apply then edit/Cancel, overlap rejection, exact missing-key/section rollback, raw blank text, strict malformed transfer values, legacy Update, and native base.write followed by ConfigObj settings.ini reload.

The original 42-harness baseline passed against unchanged NVDA reference `2843e703c`. New domain tests ran RED before implementation. Three preset harnesses cover strict version/record validation, canonical defaults, CRUD, opaque nested future fields/domains, actual settings.ini/ConfigObj save/reload, real participating panels with mutable control doubles, individual new domains in both directions, combined load, native raw presence/value restoration, profile switching, stale-copy events, modified/discard status, legacy Update, Apply/OK/Cancel/Close, and unrelated data preservation. Full verification includes NVDA-master compatibility.

The transfer increment adds a separately auto-discovered harness covering bound Import/Export handlers, single-record/opaque-field round trips, malformed UTF-8/JSON, duplicate keys, null/Boolean/future versions, numeric overflow, file/capacity bounds, atomic replacement failure, naming/file cancellation, modal teardown, staged CRUD and Apply/OK/Cancel/Close, and the real native base.write wrapper followed by settings.ini reload. Recursive packaging is checked against an actual archive for `settings/presets/transfer.py`. Final `scripts/verify.py` execution passed 46 harnesses / 927 tests with no skips against unchanged NVDA reference `2843e703c`; changed Python files also compiled and `git diff --check` passed.

These are source/control-double tests, not live wx keyboard routing, NVDA speech or visual clipping certification. No deployment/restart, commit, push, merge or release belongs to this increment. Preserve the current working runtime; independent review and a separately authorized live trial remain delivery gates.

The startup-announcement increment first reproduced missing-domain failures in its focused harness, then passed full verification: 47 harnesses / 937 tests, no skips, using the existing NVDA Python 3.13 venv and explicit unchanged reference `2843e703c`.
